# Phase 1 — Security Verification & Control Boundary Report

**Document ID:** `GCAC-PH1-SEC-VERIFY`  
**Phase:** Phase 1 — P0 Containment and Core Integrity Fixes (`Gate G1`)  
**Policy Baseline:** `Agentic_Vulnerability_Remediation_Updated_From_Clear_Photos.pdf` (`SEC-01`..`SEC-10`, §16–§19)

---

## 1. Security Verification Summary

Phase 1 eliminates **local active bypasses, unscreened extension LLM dispatch, autonomous agent Git push/PR publication, multi-finding execution, severity downgrade override paths, Webview CSP weaknesses, local HTTP preview backdoors, and shell-interpolated scanner commands**. Controls are backed by deterministic code enforcement and negative security regression tests rather than prompt instructions alone.

---

## 2. Explicit 9-Path Security & Enforcement Boundary Disclosure

Per Phase 0 ADR-001 and `00_threat_model.md`, an enterprise product audit must accurately distinguish **codebase-enforced runtime controls** from **VS Code / Copilot platform limits** and **external enterprise infrastructure dependencies**:

| # | Execution Path | Enforced Mechanism in Codebase | Verified Guarantee | Architectural Boundary / Limitation Remaining |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **Extension `vscode.lm` Calls** (`extension/llmClient.js`, `remediationEngine.js`) | `OutboundContextGate.assertAllowed()` runs fail-closed before `getAvailableModels()` & `sendRequest()` | Blocks secrets (`sk_live_`, `ghp_`, `AKIA`, JWT, conn strings, private keys), high-entropy literals (`>=3.85` bits/char), PII (SSN/PAN/email), restricted paths (`.env`, `.github/`, `vulnerabilities.csv`), binary/NUL bytes, oversize contexts, multiple files, and prompt injection markers; emits redacted audit log tagged by `runId` | Applies strictly to calls initiated by extension JS via `vscode.lm`; does not inspect direct Copilot Chat UI traffic. |
| **2** | **Native GitHub Copilot Chat & Built-in IDE Tools** (`workbench.action.chat.open`, `@vulnerability-orchestrator`, Agent Mode) | Workspace hygiene (`.github/` bypass prompt removal, removed `approve_pr`/`publish_remediation_pr`/`execute_batch_remediation` tools, disabled auto-seeding), `.vscode/settings.json` `chat.tools.terminal.autoApprove: false` list | Removes instructions telling Copilot to ignore read-only blocks or emit fake `PASS`; removes auto-approve for `git`, `gh`, `az`, `curl`, package publish CLIs in IDE terminal prompt; minimizes local master exports/MCP exposure | **VS Code Extension API cannot intercept, decrypt, or MITM Copilot Chat's internal HTTP requests or built-in workspace `#codebase`/terminal tools.** `autoApprove: false` requires manual terminal prompt refusal rather than OS kernel sandboxing. | **9** | **Enterprise Server, Identity & Infra Controls** (`SEC-01`, `SEC-03` vault, `SEC-04` SWG/DLP, `SEC-05` SSO, `SEC-06` WORM ledger, `SEC-07` sandbox, `SEC-08` GH Rulesets, `SEC-10` retention) | Out of scope per Phase 1 strict architecture constraint (no SharePoint, SIEM, new auth server, cloud APIs, DBs) | Documented honestly as `NOT IN PHASE 1 / EXTERNAL INFRA` | Scheduled for Phases 2–4 once GitHub Enterprise, Entra ID, SharePoint, SWG/DLP, SIEM, and isolated CI runners are integrated. |

## 3. Plan B `SEC-01`..`SEC-10` Progression Assessment (Phase 0 vs. Phase 1)

| Requirement | Phase 0 Baseline | Phase 1 Status | Evidence Backing Phase 1 Rating |
| :--- | :---: | :---: | :--- |
| **`SEC-01`** Default-deny commands, paths & publishing | **FAIL** | **PARTIAL** | Agent tools/MCP/CLI/PR publish disabled; `shell: false` in adapters/testRunner; terminal `autoApprove: false` configured. OS/Execution Gateway sandbox remains Phase 3 (`External Infra`). |
| **`SEC-02`** One finding & one app per execution | **FAIL** | **PASS (Local)** | `validateSingleExecutionRequest`, single non-empty `Application_Number`/`Repository` + ambiguity check, MCP `IsValidSingleFindingId`, `.NET` `ExecuteBatchRemediation` blocked, batching kept strictly planning-only. Verified by automated negative tests. |
| **`SEC-03`** Zero master exports / PII / secrets in agent workspace context | **FAIL** | **PARTIAL** | `buildMinimizedSingleFinding`, `MinimizedFindingExtract`, and SQLite `QuarantineSensitiveHistoricalMetadata` strip PII/infra/`RawValues`; MCP `get_vulnerability`/`get_remediation_context` return minimized masked views; `GCAS_AUTO_SEED_SAMPLES` opt-in only. Historical `vulnerability/vulnerabilities.csv` (`17` test/demo rows) and seeder templates remain in repo until Phase 4 SharePoint externalization; pre-existing sample folder `remediation-output/VUL-POC-003/` preserved for historical parser compatibility. |
| **`SEC-04`** 100% AI context screening + `runId` correlation | **FAIL** | **PASS (Extension `vscode.lm`) / PARTIAL (Overall)** | 100% of `llmClient.js` calls gated fail-closed by `OutboundContextGate` with redacted `runId` logs. | **`SEC-05`** Authenticated, non-self, diff-bound Gate 1 approval | **FAIL** | **PARTIAL** | All unauthenticated Gate bypasses removed (`approve_pr` auto-default removed, autonomous publish disabled, `/api/approve-final` disabled); `proposedDiffSha256` drift detection added before Stage 5 resume.
