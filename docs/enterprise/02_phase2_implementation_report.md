## 2. Explicit Engineering Honesty & Control Boundary Matrix

| Boundary Domain | What Phase 2 Enforces Locally | What Phase 2 Does **NOT** Guarantee (Explicitly Deferred / Platform Limits) |
| :--- | :--- | :--- |
| **Prompt Injection (`ContentInjectionScreen`)** | Screens C#/Java comments, scanner text, CSV/Excel fields, test logs, Markdown reports, READMEs, and model outputs via structured versioned rules (`GCAC-PH2-INJ-1.0`: `INJ-001`..`INJ-013`). | Pattern-based screening is defense-in-depth, not bypass-proof against novel natural-language phrasing or obfuscation beyond bounded Base64/URL/hex checks. |
| **Workspace Isolation (`IsolatedWorkspaceManager`)** | Separates working tree edits into per-run detached Git worktrees outside developer checkouts; preserves uncommitted WIP; rejects remote Git URLs and non-Git directories; bounds cleanup inside `runsRoot`. | **Not a security sandbox.** Processes still inherit developer OS user permissions, cached credentials, and host network stack; OS/container sandboxing (`SEC-07`) belongs to **Phase 3**. |
| **Human Approval (`ApprovalGovernance`)** | Enforces diff-SHA-256, file manifest, `runId`, base commit, single-use Stage 5 consumption, expiry, and fail-closed verification via `LocalPoCApprovalProvider` vs `EnterpriseIdentityApprovalProvider`. | Local IDE usernames and local JSON digests are **not authenticated non-self approval** (`AUTHENTICATION_NOT_VERIFIED` recorded explicitly; `requireAuthenticatedApproval` fails closed). Native Copilot Chat file-edit tools cannot be intercepted by extension UI buttons (`COPILOT_APPROVAL_LIMITATION_DISCLOSURE`). |
| **Test Weakening & Scope (`RemediationScopeGate`)** | Blocks protected paths (`.github/`, `.vscode/`, `.agents/`, `.env`, `vulnerabilities.csv`), vendored/framework paths, symlinks, suppressions (`#pragma`, `@SuppressWarnings`, `[SuppressMessage]`), skip attributes, trivial `Assert.True(true)`, and net assertion drops using pre/post disk snapshots + Git status. | Syntactic checks cannot detect subtle semantic weakening (e.g., altering test fixtures so an exploit input is no longer exercised); disclosed via `TEST_WEAKENING_DETECTION_LIMITATIONS`. |
| **RCA & Source-to-Sink (`RemediationDecisionEngine`)** | Extracts candidate entry source, dangerous sink line/snippet, missing validation pattern, and escalates high-blast-radius migrations or unsupported findings to `MANUAL_REVIEW`. | Explicitly sets `formalTaintProofSupplied: false` when operating via heuristic single-file analysis without external CodeQL/SARIF `codeFlows`. |
| **Agent Config Baseline (`AgentConfigIntegrity`)** | Verifies all 11 `.github/agents/*.agent.md` files and `.github/copilot-instructions.md` against extension-packaged `approved-agent-bundle.json`. | Protects extension-governed orchestration runs against local tampering; central immutable `.github-private/agents` distribution & PKI signatures belong to **Phase 4**. |
| **Evidence Integrity (`EvidenceLedger` & `.NET` `EvidenceGeneratorService`)** | SHA-256 artifact digests + sequential `prevHash -> eventHash` hash chaining (`events-chain.jsonl`) + `reportParser` fail-closed downgrade on `TAMPERING_DETECTED`, while keeping historical `output/*.md` reports readable as `LEGACY_NO_MANIFEST`. | Local digests and hash chains are **tamper-detectable only**, not cryptographically WORM-immutable (`LOCAL_TAMPER_DETECTABLE_NOT_WORM`). Immutable off-host WORM storage belongs to **Phase 4**. |

## 3. Defects Discovered & Remediated During Phase 2 Verification

1. **Padded Base64 Regex Bypass (`ContentInjectionScreen.js` & `ContentInjectionScreen.cs`):** Word-boundary `\b` after trailing `=`/`==` Base64 padding caused Base64 smuggling payloads ending in `=` to fail matching. Replaced with lookarounds `(?<![A-Za-z0-9+/])([A-Za-z0-9+/]{24,}={0,2})(?![A-Za-z0-9+/=])`.
2. **Windows 8.3 Short Path vs Git Top-Level Mismatch (`isolatedWorkspaceManager.js`):** Windows `os.tmpdir()` returns DOS 8.3 paths (`C:\Users\SAIGAN~1\...`) while `git rev-parse --show-toplevel` returns long paths, causing spurious containment failures. Added `canonicalExistingPath` (`fs.realpathSync.native`) normalization across `workspaceRoot`, `runsRoot`, `rawRepoAbs`, `gitTopLevel`, and cleanup targets.
3. **C# `.TrimStart('.', '/')` Stripping Dotfiles (`SecurityReviewAgent.cs`):** Calling `.TrimStart('.', '/')` stripped leading `.` from `.github/...`, `.vscode/...`, and `.env`, bypassing protected-path detection (`"github/..."`). Fixed with `Regex.Replace(..., @"^(?:\./)+", "")` and verified by `Phase2SecurityTests`.
4. **Stage 8 Resume Post-Apply Snapshot Drift (`remediationEngine.js`):** On the second resume (`isHumanApproved: true, isFinalApproved: true`), the approved patch had already been written at Stage 5, causing `preSnapshot == postSnapshot` (`filesChanged: []`) and `POST_APPLY_FILE_MISMATCH`. Fixed to verify `expectedPostApplySha256` against disk on Stage 8 resume while preserving Stage 6 post-test snapshot containment.
5. **Stage 5 vs Stage 6 `retryStage` Approval Replay & Clean Snapshot (`remediationEngine.js`):** Retrying Stage 5 (`<= 5`) now restores the original snapshot and invalidates prior Stage 4/5 approval (`stage4Approved = false`, `approvalRecord = null`) so re-application requires fresh human approval, while retrying Stage 6 (`>= 6`) re-verifies `expectedPostApplySha256` and re-runs tests without weakening single-use approval replay blocking.
